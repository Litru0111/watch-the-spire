# tools/dev — 开发调查脚本

这里的脚本是**逆向工程期间的一次性工具**，用来摸索游戏数据的结构：
存档字段含义、`.pck` 的本地化表排布、程序集元数据与 IL 形态。

## 定位

**它们不是回归测试**，不会在 CI 里跑，也不需要保持绿色。
保留它们只是为了能追溯「当时那个结论是怎么得出来的」——
比如「中文为什么是第 13 个语言」「升级增量是怎么从 IL 里取的」。

## 前提

多数脚本需要：

- 已安装的游戏（`STS2MON_GAME` 或自动探测）
- 真实的 mod 状态文件与存档
- 有时还需要 `logs/godot.log` 里有战斗记录

缺少这些时会直接报错退出，这是预期行为。

| 前缀 | 含义 |
|---|---|
| `probe_*` | 探查某个数据源里到底有什么字段/结构 |
| `dbg_*` | 针对某个具体 bug 的定位脚本 |

## 使用

```bat
python tools\dev\probe_run.py           :: 看一份 .run 存档里的全部字段
python tools\dev\probe_pck_all.py       :: 看 .pck 里能扫出哪些键
python tools\dev\probe_metadata.py      :: 看程序集里的卡牌类与数值
```

## 约定

这些脚本和主代码一样，**不写死本机路径与账号 ID**：

- 游戏/工坊目录走 `sts2mon.paths`
- 本机 Steam ID 用 `sts2mon.paths.local_steam_id_hint()` 运行时推导

如果你在这里加新脚本，请遵守同样的约定 —— 写死的盘符意味着只有你能跑，
写死的账号 ID 则是隐私泄露。
